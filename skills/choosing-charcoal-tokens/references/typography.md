# タイポグラフィガイドライン

Charcoal のテキストスタイルを選ぶときの指示。トークン名を使う。テーマごとの文字サイズと行の高さは、この文書では定めない。

見本は用途の確認用である。見本に現れるスタイル名は、その見本で使ったものであり、スタイルの全一覧ではない。

## 4種のテキストスタイル

各プラットフォームのテキストスタイルと、APCA（アクセシビリティ基準）での定義を踏まえ、Charcoal のテキストスタイルは次の4種類だけである。文章はこの4つから選ぶ。5種類目を作らない。

### Body

`Body` はデフォルトのテキストスタイルである。見出しを除く多くの文章に広く使う。

次の場面を想定する。

- コンテンツの補足情報（説明文、傍白、ネタバレ、「続く」など）
- 進行中のタスクに貢献するテキスト（ボタン、コールアウト、エラーメッセージ）
- 主要なナビゲーション
- ユーザー入力（フォームなど）
- ユーザー操作で表示されるコンポーネント（ツールチップ、メニュー、モーダル）

見本は Tab、Text Field、Switch、Pulldown Menu、Toast、Modal で、ラベルは `body` の Bold、Regular、および Compact 密度の Bold と Regular である。

### Caption

`Caption` は補助的な文に使う。

次の場面を想定する。

- コンテンツやタスクの進行に直接貢献しない情報
- 二次的なナビゲーション
- 脚注、フッター
- 著作権表記（© / ™ / CC BY-SA など）

`Caption` は小さく可読性がやや低い。控えめに使う。`Caption` と `Body` で迷った場合は、まず `Body` を選ぶ。

見本では、掲載情報に `caption.Regular.M`、著作権表記に `caption.Regular.S` を使っている。

### Heading

`Heading` は見出しに使う。

次の場面を想定する。

- ページタイトル、セクションの見出し
- コンテンツのタイトル
- モーダルのタイトル
- 短くインパクトのあるメッセージ

サイズは9種類あり、iOS / iPadOS、Android、Web で使われる典型的な見出しに対応する。サイズを順番に使う必要はない。シンプルな画面では、隣のサイズを1段飛ばして選ぶと、階層の違いが明確になる。

見本では見出し1が `heading.M`、見出し2が `heading.XS` で、あいだの `heading.S` を飛ばしている。

### Paragraph

`Paragraph` は3行以上続くコンテンツに使う。3行未満になる可能性がある場合は `Body` を使う。

見本の長文には `paragraph.Regular` を使っている。

### 選び方

- 見出しは `Heading` を使う。
- 3行以上続き、3行未満にならない本文は `Paragraph` を使う。
- 見出し以外の UI 上の文章、および3行未満になり得る本文は `Body` を使う。
- タスクに直接貢献せず、小さくてよい補助情報は `Caption` を使う。
- `Caption` と `Body` で迷ったら `Body` を選ぶ。



## Heading

見出しのサイズはこの9つから選ぶ。表に無いサイズを作らない。

「サイズの対応」は、そのサイズが各プラットフォームのどの見出しに相当するかである。HTML の見出しレベルを、この対応以外のトークンに割り当てない。`heading.XXXL` から `heading.L` は、いずれも Web では `<h1>` に相当する。


| トークン           | 使うとき                                          | サイズの対応                                        |
| -------------- | --------------------------------------------- | --------------------------------------------- |
| `heading.XXXL` | ページの中で最大の見出し。宣伝などでの利用がふさわしい。                  | iOS: Large Title。Android: Display。Web: `<h1>` |
| `heading.XXL`  | 大きい見出し。                                       | Web: `<h1>`                                   |
| `heading.XL`   | 大きい見出し。Compact 密度でも、WCAG が定義する「大きな文字」に相当する。   | Web: `<h1>`                                   |
| `heading.L`    | やや大きめの見出し。                                    | iOS: Title 1。Android: Headline。Web: `<h1>`    |
| `heading.M`    | よく使われるデフォルトの見出し。                              | Web: `<h2>`                                   |
| `heading.S`    | やや小さめの見出し。                                    | iOS: Title 2。Web: `<h3>`                      |
| `heading.XS`   | よく使われる小さめの見出し。`Body` との区別が難しいため、異なる色の使用を推奨する。 | iOS: Title 3。Android: Headline。Web: `<h4>`    |
| `heading.XXS`  | 小さめの見出し。`Body` との区別が難しいため、異なる色の使用を推奨する。       | iOS: Headline。Android: Title。Web: `<h5>`      |
| `heading.XXXS` | 小さめの見出し。`Body` との区別が難しいため、異なる色の使用を推奨する。       | iOS: Subhead。Web: `<h6>`                      |


`heading.XS`、`heading.XXS`、`heading.XXXS` は、`Body` と同じ色にしない。

## Body

本文の太さはこの2つから選ぶ。表に無い太さを作らない。


| トークン           | 使うとき                                    | サイズの対応                                |
| -------------- | --------------------------------------- | ------------------------------------- |
| `body.Regular` | 国際標準、学会研究、業界研究などを参考にした可読文字サイズ。本文の規定の太さ。 | iOS: Body。Android: Body。Web: `<body>` |
| `body.Bold`    | `body.Regular` を強調し、コントラスト比を上げる。        | `body.Regular` と同じサイズ。                |


強調しない本文は `body.Regular` を使う。強調するときだけ `body.Bold` を使う。

## Paragraph

長文の太さはこの2つから選ぶ。表に無い太さを作らない。


| トークン                | 使うとき                                  | サイズの対応                      |
| ------------------- | ------------------------------------- | --------------------------- |
| `paragraph.Regular` | 3行以上の長文に使うスタイル。長文の規定の太さ。              | Web: `<p>`                  |
| `paragraph.Bold`    | `paragraph.Regular` を強調し、コントラスト比を上げる。 | `paragraph.Regular` と同じサイズ。 |


3行以上続き、3行未満にならない本文は `paragraph.Regular` を使う。強調するときだけ `paragraph.Bold` を使う。

## Caption

補助文のサイズと太さはこの4つから選ぶ。表に無い組み合わせを作らない。


| トークン                | 使うとき                                            | サイズの対応                                                         |
| ------------------- | ----------------------------------------------- | -------------------------------------------------------------- |
| `caption.Regular.M` | Caption のデフォルトスタイル。Caption にはこのスタイルだけを使うのが望ましい。 | iOS: Callout、Footnote。Android: Label。Web: `<footer>`、`<small>` |
| `caption.Bold.M`    | `caption.Regular.M` を強調し、コントラスト比を上げる。           | `caption.Regular.M` と同じサイズ。                                    |
| `caption.Regular.S` | 極力避けるべき最小文字。                                    | iOS: Caption 1、Caption 2。Web: `<small>`                        |
| `caption.Bold.S`    | `caption.Regular.S` を強調し、コントラスト比を上げる。           | `caption.Regular.S` と同じサイズ。                                    |


Caption の規定は `caption.Regular.M` である。`caption.Regular.S` と `caption.Bold.S` は、最小文字が必要な場合に限る。強調するときだけ、同じサイズの Bold を使う。

## 5つの言語を考慮

Charcoal が重点的に考慮する言語は、ISO 639-1 順で、英語、日本語、韓国語、簡体字中国語、繁体字中国語である。

組版の文化、使えるフォント、タイポグラフィの特徴は言語によって異なる。これらの言語に広く通用する手段を優先して選ぶ。言語ごとの特殊な組み方を、この5言語へ広がらない前提で採用しない。

同じ Unicode のグリフでも、言語によって書き方や配置が異なる。グリフが同じであることを、字幅・位置・字形が同じであることの根拠にしない。

## 字幅

基本は次のとおり。

- プロポーショナル：欧文、数字
- 全角かつ等幅：仮名、ハングル、漢字

欧文と数字には半角文字とプロポーショナルフォントを使う。仮名には全角文字のフォントを使う。全角の欧文や数字、半角のカタカナは使わない。

例外は次のとおり。

- 表などで数値を比較するときは、フォントの等幅数字（Tabular Figures）を、等幅フォントより優先して使う。
- プログラミングのコードは、可読性のために等幅フォントを使う。



## 色

タイポグラフィのスタイル定義に色は含まれない。カラーは文字色のトークンと組み合わせる。文字色は `text` の節に従う。

## 字間

デフォルト値を使う。手段としてフォントのオプティカルサイズも使える。言語や文書の役割ごとの字間調整は、今後の予定であり、現在の指定ではない。役割や言語を理由に字間を変えない。

## 行長

複数行になる可能性のある文書を、Charcoal では「長文」と呼ぶ。長文の行長は閲覧体験に大きく影響する。

- 英語と韓国語では 50〜70 文字、日本語と中国語では 20〜30 文字が理想である。
- 行長は全角文字の倍数であることが理想である。実際には文字サイズの倍数として扱う。これでほぼ問題なく調整できる。これは、5言語で組版の要件が異なるためである。

見本が示す推奨範囲は、全角文字で最小 20、デフォルト 28、最大 42 である。この見本は推奨範囲の例である。長文の行長は、この範囲に収める。

## 行揃え

左揃えを基本とする。両端揃えは欧文を含む一部言語で読みづらくなるため禁止する。

## その他属性

- アンダーラインは、文書中に現れるリンクにだけ使う。強調には使わない。
- イタリック体と斜体は使わない。多言語対応が難しい。
- 大文字は、略語や小見出しにだけ使える。多言語対応にならないため、他の強調手段と合わせて使う。
- 段落インデントは UI では使わない。
- 段落間隔は UI では使わない。コンテンツ向けにカスタマイズする場合は、行間の 0.5 倍単位で調整する。
- リスト間隔は UI では使わない。
- テキストの省略と最大行数は、なるべく使わない。使う場合は全文を確認できる手段を提供する。最大行数はケースごとに決める。共通の行数を決めない。



## ポイント



### 可読性を重視する

可読性とアクセシビリティは Charcoal 全体で重視する。そのため、なるべく大きなフォントサイズを使い、ユーザーが見慣れているフォントを優先して採用する。小さいサイズや、見慣れないフォントを先に選ばない。

### スタイルの種類は最小限にする

1画面で使うテキストスタイルの種類は、できるだけ少なくする。

- 多くのスタイルを混在させると、情報の階層が不明瞭になり、可読性が下がる。
- 一貫性のないデザインは視認性を損ない、全体の印象を悪くすることがある。

一つのまとまりでは、同じ密度の `Heading`、`Caption`、`Body` を組む。密度をまたいで混ぜない。見本の密度は Compact、Default、Cozy である。同じ密度内のスタイルを使うと、シンプルで見やすい階層を作れる。

### ヒエラルキーを作る

明確なビジュアルヒエラルキーは、可読性と視認性を上げ、ユーザーが重要なコンテンツを早く見つける助けになる。そのためにタイポグラフィを使う。

文字で階層を調整する手順は、次の順である。色や太さから始めない。

1. テキストスタイルを使う。見出しや重要なコンテンツに注目が集まるようにする。太さが2種以上ある場合は、まず標準の太さのスタイルを選ぶ。この段階の色は、デフォルトの文字色 `text` を使う。文書中の表記は `color.text` である。
2. 太さを調整する。コントラスト比が低そうな箇所、階層が曖昧そうな箇所を探し、文字の太さを調整する。数値の閾値はこの節では定めていない。
3. 色で明確にする。この段階は任意である。ここまでで階層がまだ曖昧な場合にだけ、色を使って主要、二次的、三次的な要素を区別する。

見本はフォロワー一覧で、左から次の3段階である。

1. 標準の太さでテキストスタイルを適用する。
2. 太さの調整を試す。
3. 必要に応じて色を変える。この見本では補助要素を薄くしている。薄くすること自体が条件ではなく、主要、二次的、三次的を区別する一例である。
